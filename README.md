# Telegram-бот на базе GigaCode

Бот, который отвечает в Telegram через ваш локальный прокси `server.mjs`
(GigaCode → OpenAI-совместимый API). **Без зависимостей** — только Node.js ≥ 18,
`npm install` не нужен.

```
Telegram  ⇄  bot.mjs  ⇄  server.mjs (прокси)  ⇄  gigacode.ru
                    ↑
        http://127.0.0.1:8000/v1
```

Что умеет:

- диалог с моделью GigaCode прямо в Telegram, ответ печатается потоком;
- Markdown → аккуратная разметка Telegram: код с языком, таблицы, цитаты, ссылки, списки;
- история на каждый чат, обрезается по бюджету (по умолчанию 40 сообщений / 60k символов);
- **текстовый режим**: модель не мультимодальная, поэтому фото/голос/видео/стикеры бот
  честно отклоняет с подсказкой, что прислать вместо них (отключается `BOT_TEXT_ONLY=0`);
- **очередь вопросов**: можно писать не дожидаясь ответа — сообщения обработаются по порядку
  (до `BOT_QUEUE_MAX`, дальше бот предупредит);
- **продолжение оборванного ответа**: если модель упёрлась в лимит длины, под сообщением
  появляется кнопка «➡️ Продолжить» (и команда `/continue`);
- **ответы файлом**: длинные ответы можно получить как `.py`/`.js`/`.md` — кнопкой
  «📄 Прислать файлом», командами `/save` и `/export` (`/export json` — вся переписка в JSON);
- **меню `/settings`**: модель, показ размышлений, потоковый вывод — кнопками, на каждый чат;
- команды `/new`, `/retry`, `/continue`, `/save`, `/export`, `/model`, `/system`, `/settings`,
  `/stats`, `/health`, `/cancel`, `/id`, `/help`;
- кнопки под ответом: «Стоп», «Ещё раз», «Продолжить», «Прислать файлом», «Новый диалог»;
- 👀-реакция на принятый вопрос;
- приём текстовых файлов (.py, .js, .md, .json, .log, .csv …) — файл уходит в контекст;
- ответ на любое сообщение цитируется в вопросе;
- белый список пользователей (по умолчанию бот закрыт — просит прислать ваш user id);
- лимит частоты `BOT_RATE_LIMIT` запросов в минуту на пользователя;
- авто-запуск прокси, если `server.mjs` лежит рядом и ещё не запущен.

## Быстрый старт

1. **Токен.** В Telegram напишите [@BotFather](https://t.me/BotFather) → `/newbot` →
   имя и username → скопируйте токен вида `123456789:AA...`.

2. **Впишите токен** в `env.txt` рядом с ботом (файл уже есть — допишите строку):

   ```
   TELEGRAM_BOT_TOKEN=123456789:AA...
   ```

   Можно и без файла: `node bot.mjs --token 123456789:AA...` или переменная окружения.

3. **Запустите:**

   ```bash
   node bot.mjs
   ```

   Бот сам проверит прокси: если `server.mjs` лежит рядом и не запущен — поднимет его
   (`BOT_AUTOSTART_PROXY=1`), если запущен — просто подключится.

4. В Telegram отправьте боту `/start`. Если белый список не настроен, бот ответит
   вашим user id — впишите его в `env.txt` и перезапустите:

   ```
   BOT_ALLOWED_USERS=123456789
   ```

   (Либо, на свой риск, `BOT_ALLOW_ALL=1` — пустит всех.)

## Файлы

| Файл | Что это |
|------|---------|
| `bot.mjs` | сам бот (long polling, поток ответа, команды) |
| `format.mjs` | Markdown → HTML Telegram и нарезка длинных ответов |
| `server.mjs` | ваш GigaCode-прокси (не менялся) |
| `env.txt` | настройки: логин GigaCode + `TELEGRAM_BOT_TOKEN` + `BOT_*` |
| `bot-state.json` | история диалогов (создаётся автоматически) |
| `test/selftest.mjs` | сквозной тест бота на заглушках Telegram и прокси |
| `test/edge.mjs` | тесты разметки, нарезки, ошибок прокси, «Стоп», доступа |
| `start-bot.bat` / `start-bot.sh` | запуск двойным кликом / из консоли |

## Команды

| Команда | Действие |
|---------|----------|
| `/new` (`/reset`, `/clear`) | начать новый диалог, очистить контекст |
| `/retry` | повторить последний вопрос |
| `/continue` | продолжить оборванный ответ |
| `/save` | прислать последний ответ файлом |
| `/export` | выгрузить всю переписку файлом (`.md`; `/export json` — в JSON) |
| `/settings` | меню настроек чата кнопками |
| `/cancel` (`/stop`) | прервать генерацию и очистить очередь |
| `/model` | показать модель и список доступных; `/model CodeChat` — переключить |
| `/system` | показать системный промпт; `/system Ты — эксперт по C#` — задать, `/system -` — сбросить |
| `/stats` | сколько сообщений в контексте, какой прокси и модель |
| `/health` | статус прокси и авторизации в GigaCode |
| `/id` | ваш user id (для белого списка) |
| `/help` | справка |

Свои настройки чат хранит отдельно: у каждого чата своя модель, свой системный промпт и своя история.

## Настройки (env.txt или переменные окружения)

Переменные окружения имеют приоритет над файлами; читаются `env.txt`, `.env`,
`bot-env.txt` из текущей папки и из папки со скриптом.

| Переменная | По умолчанию | Значение |
|------------|--------------|----------|
| `TELEGRAM_BOT_TOKEN` | — | токен от @BotFather (обязателен) |
| `TELEGRAM_API_BASE` | `https://api.telegram.org` | адрес Bot API (менять не нужно) |
| `PROXY_URL` | `http://127.0.0.1:8000/v1` | куда бот стучится за ответами |
| `PROXY_HOST`, `PROXY_PORT` | `127.0.0.1`, `8000` | те же настройки, что у прокси |
| `MODEL_NAME` | `CodeChat` | модель по умолчанию |
| `BOT_SYSTEM_PROMPT` | ассистент-помощник | системный промпт по умолчанию |
| `BOT_HISTORY_MAX_MESSAGES` | `40` | сколько сообщений помнить |
| `BOT_HISTORY_CHAR_BUDGET` | `60000` | бюджет контекста в символах |
| `BOT_MAX_TOKENS` | `0` | 0 — длину ответа решает модель |
| `BOT_TEMPERATURE` | пусто | пусто — не вмешиваться в настройки модели |
| `BOT_SHOW_REASONING` | `0` | показывать ли размышления модели отдельным блоком |
| `BOT_STREAM` | `1` | печатать ответ по мере генерации |
| `BOT_ALLOW_ALL` | `0` | пустить всех (иначе — только `BOT_ALLOWED_USERS`) |
| `BOT_ALLOWED_USERS` | пусто | user id через запятую |
| `BOT_ALLOW_GROUPS` | `0` | разрешить работу в группах (по упоминанию бота) |
| `BOT_AUTOSTART_PROXY` | `1`, если рядом есть `server.mjs` | поднимать прокси автоматически |
| `BOT_TEXT_ONLY` | `1` | модель текстовая: отклонять фото/голос/видео с подсказкой |
| `BOT_QUEUE_MAX` | `3` | сколько вопросов можно поставить в очередь |
| `BOT_RATE_LIMIT` | `0` | запросов в минуту на пользователя (0 — без лимита) |
| `BOT_REACTIONS` | `1` | ставить 👀 на принятый вопрос |
| `BOT_FILE_AFTER_CHARS` | `2500` | с какой длины ответа предлагать «Прислать файлом» |
| `BOT_PROXY_DIR` | папка бота | где искать `server.mjs` |
| `BOT_STATE_FILE` | `bot-state.json` | файл истории |
| `BOT_LOG_FILE` | пусто | дублировать лог в файл |
| `BOT_IDLE_TIMEOUT_MS` | `180000` | сколько молчания прокси считать обрывом |
| `BOT_MAX_FILE_BYTES` / `BOT_MAX_FILE_CHARS` | `400000` / `80000` | лимиты присылаемых файлов |

## Диагностика

| Симптом | Что делать |
|---------|-----------|
| `🔒 Прокси не авторизован в GigaCode` | один раз войдите: запустите `node server.mjs` на компьютере и откройте ссылку из его лога (вход через SberID). Токен закэшируется. |
| `🔌 Прокси не отвечает` | прокси не запущен или не тот порт: `node server.mjs`, проверьте `PROXY_PORT` / `PROXY_URL`. |
| Бот отвечает «Модель работает только с текстом» | так и задумано: GigaCode не умеет смотреть картинки и слушать голосовые. Пришлите текст или текстовый файл (либо `BOT_TEXT_ONLY=0`, чтобы бот просто игнорировал вложения). |
| Ответ обрывается на полуслове | под сообщением есть кнопка «➡️ Продолжить» (и команда `/continue`). |
| Нужен ответ целиком в файле | кнопка «📄 Прислать файлом», `/save` (последний ответ), `/export` (вся переписка). |
| Бот молчит на сообщения | проверьте белый список (`/id` → `BOT_ALLOWED_USERS`) и что в логе нет `Conflict: terminated by other getUpdates` (значит, запущена вторая копия бота). |
| Телеграм не отдаёт апдейты | у бота нет вебхука: если раньше ставили — `curl "https://api.telegram.org/bot<токен>/deleteWebhook"`. |
| `TELEGRAM_BOT_TOKEN не задан` | допишите токен в `env.txt` рядом с ботом либо передайте `--token`. |
| Ответ обрывается | поднимите `BOT_IDLE_TIMEOUT_MS` и `REQUEST_TIMEOUT` у прокси. |
| Хочу «забыть» диалог | `/new` (или `/new` во всех чатах: удалите `bot-state.json`). |

Логи бота идут в консоль; `BOT_LOG_FILE=bot.log` продублирует их в файл.
Для отладки самого прокси — `GIGACODE_TRACE=1` (см. комментарии в `env.txt`).

## Тесты

Заглушки Telegram и прокси поднимаются локально, реальные токены не нужны:

```bash
node test/selftest.mjs    # сквозной сценарий: вопрос → ответ, история, команды
node test/edge.mjs        # разметка, длинные ответы, 401/502, «Стоп», доступ
node test/features.mjs    # текстовый режим, очередь, «Продолжить», файлы, /settings, лимиты
```

## Автозапуск

**Windows** — двойной клик по `start-bot.bat` (можно положить ярлык в автозагрузку:
`Win+R` → `shell:startup`).

**Linux/macOS** — `./start-bot.sh` или через nohup:

```bash
nohup node bot.mjs >> bot.log 2>&1 &
```

**systemd** (пример `/etc/systemd/system/gigacode-bot.service`):

```ini
[Unit]
Description=GigaCode Telegram bot
After=network-online.target

[Service]
WorkingDirectory=/opt/gigacode-proxy
ExecStart=/usr/bin/node /opt/gigacode-proxy/bot.mjs
Restart=on-failure
User=youruser

[Install]
WantedBy=multi-user.target
```

## Приватность

История диалогов хранится локально в `bot-state.json` и никуда, кроме прокси
GigaCode, не уходит. Файл не предназначен для публичного репозитория:
добавьте в `.gitignore` строки `env.txt`, `bot-state.json`, `*.log`.
